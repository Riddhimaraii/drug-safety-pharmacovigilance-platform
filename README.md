💊 Drug Safety & Pharmacovigilance Intelligence Platform

An end-to-end healthcare analytics project: it turns raw FDA adverse-event reports into an interactive dashboard that helps safety reviewers **explore reports, compare drugs, and flag unusual patterns for human review**.

## The problem
Pharmaceutical companies receive hundreds of thousands of reports of suspected adverse drug reactions. Reviewers need to quickly see what is being reported, how drugs differ, which reaction patterns look unusual, and whether the data can be trusted.

## What this project does
| Requirement | Where it lives in the app |
|---|---|
| Drug search tool | **Drug Explorer** - search by generic or brand name (e.g. "Humira" finds adalimumab) |
| Interactive charts: reactions, age groups, trends | **Drug Explorer** and **Overview** - filters for sex, age band, country, reporter type, seriousness, date |
| Compare two or more drugs | **Compare Drugs** - side-by-side outcomes, reactions, PRR heatmap, head-to-head odds ratios |
| Data-quality checks | **Data Quality** - missing values, duplicates, inconsistent records, sample bad records |
| Report flagging patterns for human review | **Review & Report** - auto-written report and a prioritised review queue (CSV export) |
| Unusual-pattern detection | **Signal Detection** - PRR/ROR screening, weekly spike detection, Isolation Forest (scikit-learn) |
| Public API extension | **Live openFDA** - live reports compared with the local quarter |

## Data at a glance (Q4 2020)
- **436,148** unique cases · **1.5M** drug-reaction rows · **12,293** MedDRA reaction terms · **2,428** primary-suspect drugs
- **86,903** drug-reaction pairs scored, **30** data-quality checks, **~5,000** fatal cases flagged for review

## Sample findings
_Generated by the pipeline; full text in [`REPORT.md`](REPORT.md)._
- **Litigation-driven reporting:** about 92% of ranitidine reports and 54% of tenofovir disoproxil fumarate reports came from lawyers, so their report counts and signals need careful interpretation.
- **Disproportionate pairs:** the screening surfaces expected, label-consistent pairs (e.g. collagenase and penile contusion, gadodiamide and nephrogenic systemic fibrosis) alongside pairs that deserve clinical review.
- **Batch submissions:** adapalene and copper show weekly report spikes hundreds of times their usual level, which more likely reflects bulk filing than a new risk.
- **Data quality:** about 47% of reports have no age, 50% no event date, and 14,814 reports look like possible duplicates.

## How it works
```
FAERS .txt files ─► build_db.py ─► SQLite (cases, drugs, reactions, signals, dq_checks, review_flags)
                       │                         │
          clean + standardise            PRR / ROR / Evans screening
                                                 ▼
                              app.py (Streamlit)  ·  report.py (REPORT.md)
```
1. **Load and clean** - keep the latest version of each case; convert age to years and weight to kg; standardise drug names to the active ingredient; drop repeated reaction terms.
2. **Quality checks** - missing values, impossible ages/weights, event dates after FDA receipt, age-group mismatches, possible duplicate reports, placeholder drug names.
3. **Signal detection** - for every primary-suspect drug and MedDRA term:
   - **PRR** = [a/(a+b)] / [c/(c+d)], **ROR** with 95% confidence interval, and chi-square
   - flagged with the **Evans criteria**: n ≥ 3, PRR ≥ 2, χ² ≥ 4
   - non-specific terms such as "Drug ineffective" are hidden by default
4. **Trend anomalies** - each drug's weekly counts are compared with its own median using a robust z-score; partial weeks are excluded.
5. **Unusual drugs** - an Isolation Forest scores each drug's overall profile (volume, % fatal, age, reporter mix, countries) and explains which features look unusual.
6. **Review queue** - high-severity items first (for example fatal cases that contain a strong signal), exportable as CSV.

## Run it yourself
```bash
git clone <your-repo-url> && cd pv-platform
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# Download FAERS quarterly ASCII files (e.g. from Kaggle or the FDA site) into data/raw/
# Needed: DEMO, DRUG, REAC, OUTC, RPSR, THER, INDI  (.txt)

python build_db.py --data-dir data/raw --db data/faers.db   # ~1 minute per quarter
streamlit run app.py
python report.py --db data/faers.db --out REPORT.md          # optional
```
Add more quarters by copying their files into `data/raw/` and rebuilding.

## Project structure
```
build_db.py        load + clean FAERS files, run data-quality checks, compute signals -> SQLite
pv_signals.py      PRR / ROR / Evans logic and weekly anomaly detection
queries.py         all SQL used by the dashboard
app.py             Streamlit dashboard (7 pages)
report.py          report generator (used by the app and the command line)
openfda_client.py  openFDA API client (extension)
```

## Limitations (important)
- FAERS reports are **voluntary and incomplete**. A report does not prove a drug caused the event, and incidence rates cannot be calculated because the number of people taking each drug is unknown.
- Reporting is influenced by publicity, litigation and product age (stimulated reporting).
- Many records lack age, sex or event dates, so some charts describe only a subset of cases.
- Duplicate detection is rule-based and approximate.
- Signals are **hypotheses for medical review**, not safety conclusions.
